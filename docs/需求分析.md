# 需求分析

## 项目背景

教师在备课时经常需要对比多本教材：同一概念在不同教材中的命名、定义、章节顺序和依赖关系可能不一致。人工整合耗时高，也难以追踪每个结论来自哪本教材、哪一页内容。Hackson5 Knowledge Integration Agent 面向 5 小时黑客松场景，提供一套可演示、可追溯的教材知识整合工作台。

## 目标用户

- 一线教师：上传教材、查看知识图谱、校正整合结果、生成备课参考。
- 教研人员：对比多本教材的知识覆盖、先修关系和重复概念。
- 课程设计者：基于整合图谱和报告规划教学路径。

## 核心需求

1. 教材上传与解析：支持 PDF、Markdown、TXT；保存教材元信息并按章节拆分。
2. 知识图谱构建：从章节中抽取知识点、定义、分类、页码、频次和关系。
3. 多教材整合：识别重复或相近知识点，给出 merge、keep、remove 等整合决策。
4. RAG 问答：对教材章节进行 chunk 切分，回答问题时返回来源引用。
5. 教师反馈：教师可通过对话纠正整合决策，系统记录覆盖标记。
6. 报告生成：输出教材处理摘要、整合质量、风险和教学建议。
7. 可视化工作台：用 ECharts 展示知识图谱，配合模式选择、进度状态、问答和报告面板。

## 模式需求

- Demo Mode：限制处理页数，优先速度和稳定演示。
- Quality Mode：处理更多页数，追求更完整的解析、抽取和报告结果。

## 非功能需求

- 可本地运行：无 DeepSeek API Key 时仍能通过确定性 fallback 完成演示。
- 可部署：前端部署到 Vercel，后端部署到 Railway。
- 可追溯：RAG 回答必须包含 chunk、章节、页码等引用信息。
- 数据安全：PDF 和上传文件不得提交到 Git。
- 可测试：后端服务和 API 可通过 pytest、ruff 验证；前端可通过 lint、format、build 验证。

## 验收标准

- 教师能上传一本或多本教材并成功运行流水线。
- 页面能展示图谱节点、边、处理状态、RAG 答案、引用和整合报告。
- 教师反馈能记录到对话并影响对应整合决策。
- `DEEPSEEK_API_KEY` 缺失时系统仍能跑通 Demo 流程。
