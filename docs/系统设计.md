# 系统设计

## 总体架构

系统采用前后端分离架构：Next.js 前端负责教师工作台和图谱展示；Django Ninja 后端负责文件上传、教材解析、LangGraph 流水线、RAG 检索、教师反馈和报告生成。

```text
Browser -> Next.js Workbench -> Django Ninja API -> LangGraph Pipeline -> SQLite/PostgreSQL
                                      |                 |
                                      |                 -> DeepSeek API or fallback
                                      -> media/textbook files
```

## 前端设计

- `frontend/app/page.tsx` 挂载 Workbench。
- `frontend/components/workbench.tsx` 提供上传、模式选择、流水线触发、状态展示、RAG 问答、教师反馈和报告面板。
- `frontend/components/graph-view.tsx` 使用 ECharts 渲染知识图谱。
- `frontend/lib/api.ts` 封装 `/api/*` 请求。
- `frontend/lib/types.ts` 维护 API 数据结构。

界面重点是演示闭环：上传教材后运行流水线，刷新图谱与报告，再通过 RAG 和教师反馈验证结果。

## 后端 API

Django Ninja 路由集中在 `apps/textbooks/api.py`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/textbooks/upload` | 上传 PDF/Markdown/TXT 教材 |
| POST | `/api/pipeline/run` | 运行教材处理流水线 |
| GET | `/api/pipeline/status` | 查询最近或指定流水线状态 |
| GET | `/api/graph` | 获取知识图谱节点和边 |
| POST | `/api/rag/index` | 为指定教材重建 RAG chunk 索引 |
| GET | `/api/rag/status` | 查看 RAG chunk 数量 |
| POST | `/api/rag/query` | 基于教材 chunk 回答问题并返回引用 |
| POST | `/api/teacher/chat` | 记录教师反馈并覆盖整合决策 |
| GET | `/api/report` | 获取最新整合报告 |

## 数据模型

- `Textbook`：教材文件、解析状态、处理模式、页数和字符数。
- `Chapter`：教材章节、页码范围、正文和顺序。
- `KnowledgeNode`：知识点名称、定义、分类、页码、频次、来源节点和是否整合。
- `KnowledgeEdge`：知识点关系，支持 prerequisite、parallel、contains、applies_to。
- `IntegrationDecision`：整合动作、涉及节点、置信度、理由和教师覆盖标记。
- `RagChunk`：RAG 文本块、页码、向量和来源章节。
- `ConversationMessage`：教师与助手的反馈对话记录。
- `PipelineRun`：流水线状态、进度、错误和汇总报告。

## 流水线设计

`apps/textbooks/services/pipeline.py` 使用 LangGraph 将处理拆成五个阶段：

1. Parse：解析教材并生成章节。
2. Graph：调用 DeepSeek 或 fallback 抽取章节知识图谱。
3. Integrate：合并跨教材相似节点并记录决策。
4. RAG：按章节切分 500-800 字 chunk，保留 80 字重叠并生成轻量向量。
5. Report：生成整合摘要、风险和建议。

每个阶段都会更新 `PipelineRun.current_stage` 和 `progress`，便于前端展示。

## AI 与 fallback

`DeepSeekClient` 读取 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL`。当 API Key 缺失或请求失败时，系统使用确定性 fallback：

- 图谱抽取基于关键词和章节内容生成基础节点、边。
- RAG 回答基于检索到的上下文生成简短回答。

这样可以保证黑客松现场即使没有外部模型凭据也能完成闭环演示。

## 部署设计

- 前端：Vercel，生产地址 `https://hackson5.vercel.app`。
- 后端：Railway，生产地址 `https://hackson5-production.up.railway.app`。
- 数据库：本地 SQLite；Railway 通过 `DATABASE_URL` 使用 PostgreSQL。
- 运行时：Railway 启动时执行迁移并用 gunicorn 提供 Django WSGI 服务。

## 数据安全

上传文件位于 media 目录，PDF 和本地教材数据被 `.gitignore` 忽略。演示或部署时应避免上传敏感、受版权保护或未经授权的教材全文。
